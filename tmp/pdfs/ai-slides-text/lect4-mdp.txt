Search Problems


Recall a search problem consists of:
    A set of states.
    A starting state.
    A set of actions that map states to states.
    Goal condition.
    Cost function: cost of doing an action.
Markov Decision Process (MDP): actions are indeterminate, the cost
function depends on the starting and ending states of the action.




        (HKUST)               Markov Decision Process                4 / 57
MDP

A MDP consists of:
    A set of states.
    A starting state.
    A set of actions modeled by a global probabilistic transition relation:
    T (s, a, s 0 ) - the probability of reaching state s 0 from s by taking
    action a.
    Reward function: Reward(s, a, s 0 ) - the reward for ending in s 0 when
    taking action a in s.
    Goal (terminating) condition: End(s).
    A discount factor 0 ≤ γ ≤ 1.

Policies




What is a solution for MDP? A solution needs to tell which action to take
in every possible situation.
A policy π is a mapping from states to actions. For example, here is a
policy for playing the dice game is: π(s) = stay if s = in, and nil
otherwise. Here nil means no action, and is added so that policies are
functions: T (s, nil, s) = 1 and Reward(s, nil, s 0 ) = 0.

Evaluating a policy


There are many policies. How do you compare them? The usual suspect:
expected utilities.

                         in, stay , 4, in, stay , 4, out

        Reward(in, stay , in) + γReward(in, stay , out) = 4 + γ × 4.

Optimal Policy and Value Function

   Policy evaluation computes the value of a state when executing the
   given policy.
   Given a MDP, we want to know the optimal policy and the optimal
   value function (maximal values of states)
   A policy πopt is optimal if for every policy π 0 , Vπopt (s) ≥ Vπ0 (s) for all
   s.
   A value function V ∗ is optimal if

                        V ∗ (s) = maxπ Vπ (s) = Vπopt (s).

   We first look at how to find an optimal policy by a hill climbing
   algorithm (policy iteration), then we look at how to compute the

Policy Improvement
Given a policy π, how to make it better?
     Better means that states have better values under the new policy.
     Recall that Vπ (s) = Qπ (s, π(s)).
     Now if we can find a policy π 0 such that
     Vπ0 (s) = maxa∈Actions(s) Qπ (s, a), then Vπ0 (s) ≥ Vπ (s). Thus π 0 will
     be as good as π, and likely better.
Policy improvement: Given a policy π, improve it to πnew :
     Compute Vπ (s) for every s.
     Compute Qπ (s, a) for every s and a in Actions(s).
     Let πnew be: for each s

                     πnew (s) = arg maxa∈Actions(s) Qπ (s, a).

So let successor (π) in policy iteration be πnew .

Exploration vs Exploitation



Given the current knowledge about the model (how the world works),
which action to take:
    Do the best action given what’s known about the world now
    (exploitation, go by the book).
    Try an action that hasn’t been tried before or did not work too well
    last time (exploration, try something new).
It’s clear that unless we have a perfect model of the world, we need to do
both.

Q-Learning
Assume we have the current estimate of Q-value, Q̂(s, a) for all state s
and action a. Now given an observed transition (S, A, r , S 0 ), update the
estimated Q-value of (S, A) as follows:

                  Q̂(S, A) = (1 − µ)Q̂(S, A) + µ(r + γ V̂ (S 0 )),

where
    µ is the learning rate;
    γ the discount factor;
    V̂ (S 0 ) = maxa∈Actions(S 0 ) Q̂(S 0 , a);
    Q̂(S, A) in the right side is the old estimate, and r + γ V̂ (S 0 ) is the
    new learned value;
    the update formula strives for a balance between the old value and
    the learned value, controlled by the learning rate µ.

Stochastic Policies



Is there any need for a stochastic policy in MDP?
    In theory: No. There is always an optimal deterministic policy.
    In practice: Yes. When there are too many actions, too many states,
    optimal policies may be impossible to compute, and deterministic
    “good” policies may not be desirable.
    Think about LLM, the next token generation as an action.

GRPO


  The PPO algorithm is expensive as it uses a large “critic” model to
  estimate the advantage (Â).
  Recall that advantage is supposed to measure the difference between
  the value of doing a (Q(s, a)) and the expected value (V (s)).
  Instead of using a large model to compute V , GRPO (Group Relative
  Policy Optimization) from DeepSeek samples a group of different
  outputs (trajectories, episodes, runs, traces, etc), calculates their
  rewards, and computes an ”advantage” by comparing each reward to
  the average reward of that group. Details in
  https://arxiv.org/abs/2402.03300
